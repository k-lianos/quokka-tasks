# Quokka Tasks v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build an offline Electron desktop app with a Monday–Sunday week view and a backlog of ordered, draggable tickets (title, description, status), stored in one local JSON file.

**Architecture:** All business rules (dates, list ordering, rollover, validation, drop rules) live in framework-free TypeScript modules under `src/domain/`, shared by the Electron main process and the Angular UI, and unit-tested with Vitest. The Electron main process (`electron/`, compiled with `tsc`) owns the data file and exposes `load`/`save` over IPC through a sandboxed preload. The Angular UI (built by the Angular CLI) keeps the ticket array in one signal-based service (`TasksStore`), applies domain functions, enforces rollover after every change, and saves the whole file. Electron Forge is used only to package.

**Tech Stack:** Electron 45, Angular 22 (standalone components, signals, zoneless) + `@angular/cdk` drag-drop, TypeScript, Vitest, Electron Forge 8 (deb + zip makers), npm. Node 22 / npm 10 on the dev machine.

**Spec:** `docs/superpowers/specs/2026-11-26-tasks-app-design.md`

## Global Constraints

- No network access at runtime: no CDN scripts, remote fonts, telemetry or update checks.
- No Linux-only APIs or hard-coded paths; use `path`, `app.getPath`, `app.getAppPath` and Electron/Node APIs that work on Linux, Windows and macOS.
- All dates are **local** calendar dates, `'YYYY-MM-DD'` strings. Never derive a date with `toISOString()`.
- Weeks run Monday–Sunday. Header label: ISO week number + date range, e.g. `Week 48 · 23–29 Nov 2026`.
- Status values `'pending' | 'in_progress' | 'completed'`, labels `Pending` / `In Progress` / `Completed`, dot colours grey / blue / green.
- Position 0 is the highest priority; card marker shows `position + 1`; positions are contiguous per list.
- Data file: `<appData>/quokka-tasks/tasks.json`, shape `{ version: 1, tickets: Ticket[] }`, written atomically (temp file + rename).
- Renderer: `contextIsolation: true`, `nodeIntegration: false`, `sandbox: true`.
- `src/domain/` and `src/shared/` import nothing from Angular, Electron, Node or the DOM (they're compiled by both builds).
- Dependencies: only the approved list in the spec's "Stack (decided)" section. Anything else needs the user's approval. All packages are devDependencies (Angular code is bundled; the main process uses only Node built-ins), so the packaged app ships no `node_modules`.
- npm uses the public registry via the project `.npmrc` (the user's global `~/.npmrc` points at a local registry that may be down).
- Conventional Commits; all work on branch `feat/tasks-app-v1` (already checked out). Never commit to `main`.
- Visual style is deliberately plain; all styles in the global `src/styles.css` (components have no style files), so restyling later happens in one place.
- Standard verification for every task: `npm test && npm run build` exits 0.

## Review Focus

1. **Whitespace-only titles** (" ") on create or edit must be rejected, not saved as blank cards. → tests in Task 3.
2. **Closing the app right after typing in the focus view** must keep the edit (debounce not yet fired). → close-flush handshake in Task 6, manual check in Task 8.
3. **Dropping onto a past day — on its empty area or on one of its cards** — must be refused. → `canDropInto` test in Task 9, plus the CDK enter predicate.
4. **Future-dated unfinished tickets and backlog tickets** must be untouched by rollover. → tests in Task 4.
5. **Very long titles with no spaces / many tickets in one day** must not break the layout: card titles ellipsize, columns scroll vertically. → CSS + manual check in Task 7.

### Task 3: Ticket list operations

**Files:**

- Create: `src/domain/tickets.ts`, `src/domain/tickets.test.ts`

**Interfaces:**

- Consumes: `Ticket`, `Status` (Task 2), `makeTicket`.
- Produces (all pure; never mutate inputs; return a new array):
    - `listOf(tickets: Ticket[], date: string | null): Ticket[]` — tickets in that list sorted by `position`.
    - `createTicket(tickets: Ticket[], args: { id: string; title: string; date: string | null; now: string }): Ticket[]` — trimmed title; appended at bottom; `status: 'pending'`, `description: ''`, `createdAt = updatedAt = now`. Returns the **same array reference** if the trimmed title is empty.
    - `updateTicket(tickets: Ticket[], id: string, patch: Partial<Pick<Ticket, 'title' | 'description' | 'status'>>, now: string): Ticket[]` — title trimmed; an empty trimmed title in the patch is ignored (other fields still apply); sets `updatedAt`. Same reference if nothing changed or id unknown.
    - `deleteTicket(tickets: Ticket[], id: string): Ticket[]` — removes and renumbers its list.
    - `moveTicket(tickets: Ticket[], id: string, toDate: string | null, toIndex: number, now: string): Ticket[]` — removes from source list, inserts at `toIndex` (clamped to `[0, len]`) in target list (computed **without** the moved ticket), renumbers source and target, sets `date` and `updatedAt` on the moved ticket. Same reference if the result is identical.
    - `renumberAll(tickets: Ticket[]): Ticket[]` — makes every list contiguous, ordering by `(position, createdAt, id)`.

### Task 5: Data file validation and storage

**Files:**

- Create: `src/domain/validate.ts`, `src/domain/validate.test.ts`, `src/shared/api.ts`, `electron/storage.ts`, `electron/storage.test.ts`

**Interfaces:**

- Consumes: `DataFile`, `Ticket`, `STATUSES`, `renumberAll`.
- Produces (`src/domain/validate.ts`):
    - `emptyDataFile(): DataFile` → `{ version: 1, tickets: [] }`
    - `parseDataFile(text: string): DataFile | null` — `null` unless: valid JSON object, `version === 1`, `tickets` is an array, every ticket has string `id` (unique), non-empty string `title`, string `description`, `status` in `STATUSES`, `date` null or matching `/^\d{4}-\d{2}-\d{2}$/`, finite number `position`, string `createdAt`/`updatedAt`. On success positions are passed through `renumberAll`.
- Produces (`src/shared/api.ts`):
    ```ts
    export interface LoadResult {
        data: DataFile;
        notice: string | null;
    }
    export interface TasksApi {
        load(): Promise<LoadResult>;
        save(data: DataFile): Promise<void>; // rejects on failure
        onFlushRequest(handler: () => Promise<void>): void; // main asks renderer to flush before closing
    }
    export const IPC = { load: 'tasks:load', save: 'tasks:save', flushRequest: 'app:flush-request', flushDone: 'app:flush-done' } as const;
    declare global {
        interface Window {
            api: TasksApi;
        }
    }
    ```
- Produces (`electron/storage.ts`): `createStore(dir: string): { load(): Promise<LoadResult>; save(data: DataFile): Promise<void> }`
    - File `path.join(dir, 'tasks.json')`; `dir` created recursively on save.
    - `load`: missing file → `{ data: emptyDataFile(), notice: null }`. Unreadable/invalid → rename to `tasks.corrupt-<stamp>.json` where `<stamp>` is `new Date().toISOString()` with `:` and `.` replaced by `-`; return empty data and notice `` `Your data file couldn't be read. It was kept as ${name} and the app started empty.` ``
    - `save`: write `JSON.stringify(data, null, 2)` to `tasks.json.tmp`, then `fs.rename` over `tasks.json`. Saves are serialized (each waits for the previous one, whether it succeeded or failed), so the last call wins.
