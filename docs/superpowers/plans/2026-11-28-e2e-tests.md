# End-to-end Tests Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Playwright suite that drives the built Electron app against seeded scratch data, ships the manual checks from past plans as tests, and runs on every PR.

**Architecture:** One fixture (`e2e/app.ts`) launches the app with `_electron.launch` and a fresh `--user-data-dir` per test, seeds `tasks.json`, and exposes the window plus a reader for the saved file. Specs find elements by role and accessible name. A new `e2e` CI job builds the app and runs the suite under xvfb.

**Tech Stack:** `@playwright/test` ^1.65.1 (`_electron`), Electron 45, Angular 22, TypeScript strict.

**Spec:** `docs/superpowers/specs/2026-11-28-e2e-tests-design.md`

## Global Constraints

- One new devDependency: `@playwright/test` (approved). No `npx playwright install`; no browsers are downloaded.
- Every launch passes `--no-sandbox`, `--user-data-dir=<fresh temp dir>` and `--lang=en-GB` (24-hour time input on every machine). `TZ=Europe/Athens` in the Playwright process and the app.
- Seed dates come from `day(offset)` relative to the real today, never literals. Past days inside a week come from the previous week.
- `retries: 0`, `trace: 'retain-on-failure'`, no `waitForTimeout`. Disk checks use `expect.poll`.
- Selectors: role, accessible name, label, placeholder, text. No CSS classes. `data-testid` only if nothing else works (say why in the commit).
- New accessible names are `aria-label`s; template event bindings still call `void` methods (AGENTS.md).
- Specs are `e2e/*.spec.ts`; Vitest's include (`*.test.ts`) must not change.
- The `ci` job is untouched; the new job is named `e2e`.
- Standard verification for every task: `npm test && npm run build && npm run test:e2e`.

## Review Focus

1. **A test reaching real data** (fixture bug, missing flag): expected to be impossible. → Task 1 test `uses the scratch data dir` asserts `app.getPath('userData')` equals the temp dir.
2. **12-hour locale on CI** turns `0930` into a half-typed time: expected `09:30` everywhere. → `--lang=en-GB` in the fixture; Task 5 `due time 0930 shows 09:30` is the guard.
3. **The weekday the suite runs on** (Monday has no past day this week, Sunday has no future one): expected the same results any day. → Task 2 helper `weekOf(offsetWeeks)`; Task 4 and Task 5 seed past days in the previous week only.
4. **A failed test leaving Electron running**, blocking later runs or hanging CI: expected clean teardown. → Task 1 teardown: `app.close()` raced against 5 s, then `app.process().kill()`; test `teardown leaves no process` checks the pid is gone.
5. **Stale or missing `dist/`** makes tests pass against old code or fail obscurely: expected a clear error. → Task 1: the fixture throws `Run npm run build first` if `dist/electron/electron/main.js` or `dist/renderer/browser/index.html` is missing.

**Interfaces:**

    - `interface Quokka { app: ElectronApplication; page: Page; dir: string; today: string; readData(): Promise<DataFile>; files(): Promise<string[]> }` — `readData` parses `<dir>/tasks.json`; `files` is `readdir(dir)` sorted.

### Task 4: Day view and drag and drop

**Files:**

- Modify: `e2e/app.ts` (drag helper)

**Interfaces:**

- [ ] **Step 1: Day view tests** (`e2e/day-view.spec.ts`), seeds on `day(0)` unless said:

    - `a past day is read-only`: ticket completed on `day(-1)`; open `#/day/<day(-1)>` → no `Up next`/`Planned`, no `+ add`, ticket under `Done`.
