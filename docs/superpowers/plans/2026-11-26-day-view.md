# Day View and Routing Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add Angular hash routing with a Day view (the start screen, with a "Now" ticket on today) beside the existing Week view.

**Architecture:** All rules are pure functions in `src/domain/`: URL ↔ view mapping and header navigation (`views.ts`), the day heading (`dates.ts`), and the Now pick, progress and Up next drop-index mapping (`day.ts`). `App` becomes a shell holding the header, banners, the `cdkDropListGroup` (wrapping `<router-outlet>` and the backlog) and the ticket editor. `WeekPage` and `DayPage` are routed. A root `Board` service owns "which ticket is open" and drop handling, so both pages and the shell share them.

**Tech Stack:** Angular 22 (standalone, signals, zoneless), `@angular/router` (new, approved), `@angular/cdk/drag-drop`, Vitest, Electron.

**Spec:** `docs/superpowers/specs/2026-11-26-day-view-design.md`

## Global Constraints

- `src/domain/` and `src/shared/` import nothing from Angular, Electron, Node or the DOM.
- Domain functions never mutate input; functions returning a view return the **same object** when nothing changes.
- Only new dependency: `@angular/router`, exactly the installed Angular version (`22.3.0`, saved as `^22.3.0`), as a devDependency, via the project `.npmrc` (public registry).
- Hash URLs only: `withHashLocation()`. URLs: `#/day/YYYY-MM-DD`, `#/week/YYYY-MM-DD` (a Monday).
- All styles in `src/styles.css`, design tokens only (no raw colours in rules), per `docs/style-guide.md`.
- `DataFile` stays `version: 1`; nothing new is stored.
- Statuses change only on a user action (Start, Done → next, the editor).
- Conventional Commits on branch `feat/day-view`. Verification: `npm test && npm run build`.
- Manual checks run against the built app with a scratch profile, never the real data:
  `npm run build && ./node_modules/.bin/electron . --no-sandbox --user-data-dir=$SCRATCH/profile --remote-debugging-port=9333`
  (drive over CDP or by hand; kill the electron PID when done).

## Review Focus

1. **Drop next to a hidden Now ticket** (Now is #2 of 4, drop between #1 and #3, or at the end of Up next): must land after Now and never displace it by position alone. → tests in Task 2.
2. **Hash navigation in the packaged/file:// build**: the `will-navigate` guard in `electron/main.ts` must not block route changes, and reloading on `#/week/…` must keep working. → manual check in Task 3 against `npm start`, not only the dev server.
3. **Odd URLs**: `#/day/2026-02-30`, `#/day/garbage`, `#/week/2026-11-26` (a Thursday) → today's day / today's day / `#/week/2026-11-23`. → tests in Task 1, manual check in Task 3.
4. **Same component, new param**: ‹ › from `#/day/a` to `#/day/b` reuses `DayPage`; everything must follow the `date` input (list, Now, progress, past/future rules). → manual check in Task 4.
5. **Now disappears under the user**: deleting the Now ticket in the editor, or setting it back to Pending while another is In Progress, must re-pick Now immediately. → test in Task 2 (`nowTicket` cases), manual check in Task 4.

### Task 1: Domain — views, URLs and the day heading

**Files:**
- Create: `src/domain/views.ts`, `src/domain/views.test.ts`
- Modify: `src/domain/dates.ts`, `src/domain/dates.test.ts`

**Interfaces:**
- Produces (in `dates.ts`):
  - `isValidDate(s: string): boolean` — `^\d{4}-\d{2}-\d{2}$` and a real calendar date (round-trips through `addDays(s, 0)`).
  - `interface DayHeading { eyebrow: string; title: string }`
  - `formatDayHeading(date: string, today: string): DayHeading` — eyebrow `'<Weekday long> · Week <isoWeek>'`, title `'<d> <Month long>'`, plus `' <yyyy>'` when the year differs from `today`'s year.
- Produces (in `views.ts`):
  - `type View = { kind: 'day'; date: string } | { kind: 'week'; weekStart: string }`
  - `viewUrl(v: View): string` — `'/day/2026-11-26'`, `'/week/2026-11-23'`.
  - `parseViewUrl(url: string): View | null` — accepts the router URL (`/day/x`, `/week/x`, ignoring any `?…`/`#…` suffix); `null` for anything else or an invalid date. Week dates are returned as given (not normalised).
  - `stepView(v: View, delta: 1 | -1): View` — day ± 1 day, week ± 7 days.
  - `todayView(kind: View['kind'], today: string): View` — `{day, today}` / `{week, startOfWeek(today)}`.
  - `switchView(v: View, today: string): View` — day → week containing the date; week → `today` if in that week, else the week's Monday.
  - `followToday(v: View, oldToday: string, newToday: string): View` — day: `date === oldToday` → newToday; week: `nextViewedWeek`. Same object when unchanged.

### Task 2: Domain — Now ticket, progress, Up next drop index

**Files:**
- Create: `src/domain/day.ts`, `src/domain/day.test.ts`

**Interfaces:**
- Produces:
  - `nowTicket(tickets: Ticket[], date: string): Ticket | null` — among `listOf(tickets, date)`: first In Progress by position; else first Pending; else `null`.
  - `dayProgress(tickets: Ticket[], date: string): { done: number; total: number }`
  - `upNextToIndex(otherOpenIds: string[], nowId: string | null, dropIndex: number): number` — `otherOpenIds` is the day's open ticket ids in priority order **excluding the ticket being dragged** (and including Now). Returns the `toIndex` for `moveTicket`.
    Rule: `visible = otherOpenIds` without `nowId`. If `dropIndex < visible.length` → `otherOpenIds.indexOf(visible[dropIndex])` (directly before the ticket below the gap); otherwise → `otherOpenIds.length` (end of the open tickets, so after Now). With `nowId === null` this is the identity.
