# Due Time Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add an optional due time (`"HH:MM"`) to dated tickets. It's edited in the focus view and shown on cards, Day rows and the Now block. Ships data version 3.

**Architecture:**

- A new 2 → 3 step in `src/domain/migrate.ts`.
- Validation is extended in `validate.ts`.
- The "no time without a day" rule is enforced in the domain (`saveTicketEdits`, `moveTicket`).
- `FocusView` gets a native time input. Three display components show the stored value as is.

**Tech Stack:** Angular (standalone, signals, zoneless), TypeScript strict, Vitest.

**Spec:** `docs/superpowers/specs/2026-11-28-due-time-design.md`

## Global Constraints

- `Ticket.dueTime: string | null`. Valid values match `/^([01]\d|2[0-3]):[0-5]\d$/` exactly.
- `date === null` implies `dueTime === null`, after every domain operation that can set either.
- Migration 2 → 3: set `dueTime: null` on every ticket object, nothing else. It overwrites a stray key. The step is a literal and is frozen once shipped.
- Fixtures are hand-written and committed. `tasks.v1.json` and `tasks.v1.migrated.json` must not change.
- Display is always 24-hour `HH:MM`: the stored string itself.
- No new dependencies. Styles only in `src/styles.css`, tokens only, no `opacity` dimming. Must fit at the 900px window width.
- UI copy, exactly: no new visible label (the time input sits in the existing `Date` row); the time input has `aria-label="Due time"`. This is the plan's reading of the spec's "a `Time` field on the Date row".
- Branch `feat/due-time`. Conventional Commits. Verify with `npm test && npm run build`.

## Review Focus

- **Typing a time by keyboard** (Chromium reports `''` while the time is incomplete): the draft must not be cleared mid-typing, and the input must not reset. The handlers follow the date field's pattern: take complete values on `change`, and settle on `blur`. Hand-checked in Task 3.
- **Clearing the time input** (the clear control or Backspace): saves as `null`, with no time shown on the card. Hand-checked in Task 3.
- **Dragging a timed ticket into the backlog:** the time is dropped. Tested in Task 2.
- **A version-2 file with a stray `dueTime` key:** it's overwritten with `null`. Tested in Task 1.
- **A long title plus a time on a week card at 900px:** the time stays visible and the title truncates. Hand-checked in Task 3.

### Task 2: Domain rules — no time without a day

**Files:**

- Modify: `src/domain/tickets.ts`, `src/domain/tickets.test.ts`

**Interfaces:**

- Consumes: `Ticket.dueTime` (Task 1).
- Produces:
    - `TicketEdits` gains `dueTime: string | null`.
    - `saveTicketEdits` stores it, but stores `null` when the effective date is `null`.
    - `moveTicket` sets `dueTime: null` on a ticket that moves into the backlog.
    - `updateTicket`'s `Patch` gains `dueTime`, and its no-change check covers it.

- [ ] **Step 1: Write the failing tests** (add `dueTime: t.dueTime` to the test's `edits()` helper):
    - `saveTicketEdits stores a due time`: `edits(a, { dueTime: '14:00' })` gives `dueTime '14:00'` and `updatedAt: NOW`.
    - `saveTicketEdits drops the due time for the backlog`: `edits(a, { date: null, dueTime: '14:00' })` gives `date: null, dueTime: null`.
    - `saveTicketEdits with only a due time change keeps the position`.
    - `moveTicket into the backlog drops the due time`: ticket `a` with `dueTime: '09:00'`, moved to `null`, gives `dueTime: null`.
    - `moveTicket between days keeps the due time`.
    - `rollover keeps the due time`: an overdue open ticket with `'09:00'` lands on today still at `'09:00'`.

- [ ] **Step 2: Run** `npx vitest run src/domain/tickets.test.ts`. Expected: FAIL. (The rollover test may already pass. That's fine: it pins current behaviour. Say so in the ledger.)

- [ ] **Step 3: Implement** in `tickets.ts`. `placeList` is shared, so apply the drop in `moveTicket` itself (only to the moved ticket, only when `toDate === null`).

- [ ] **Step 4: Run** `npm test`. Expected: PASS.

- [ ] **Step 5: Commit**: `git commit -m "feat: keep due times only on dated tickets"`

### Task 3: Focus view field and display

**Files:**

- Modify:
    - `src/app/focus-view.ts`, `src/app/ticket-card.ts`, `src/app/day-row.ts`, `src/app/now-block.ts`;
    - `src/styles.css`;
    - `docs/architecture.md` (the FocusView, TicketCard/DayRow and NowBlock notes).

**Interfaces:**

- Consumes: `TicketEdits.dueTime` (Task 2) and `DUE_TIME` (Task 1).

- [ ] **Step 1: Modal.**
    - Add a `dueTime = signal<string | null>(null)` draft, loaded in the existing effect and included in `save()`.
    - In `.field-date`, between the date input and the checkbox label, add `<input #timeInput type="time" aria-label="Due time">`. Bind `[value]="dueTime() ?? ''"` and `[disabled]="date() === null"`.
    - Keep the field's single visible label, `Date`. The time input's accessible name is `aria-label="Due time"`. The row reads as one field: date, time, backlog checkbox.
    - Handlers, mirroring `onDateTyped`/`onDateLeft`:
        - `(change)`: if the value matches `DUE_TIME`, set the draft.
        - `(blur)`: if the value is `''`, set the draft to `null`. If it's non-empty but doesn't match, put the input back to the draft.
    - `setBacklog(true)` also sets `dueTime` to `null`.

- [ ] **Step 2: Display.**
    - On `TicketCard`, `DayRow` and `NowBlock`, when `ticket.dueTime` is set, render `<span class="card-time">{{ dueTime }}</span>` next to the `.card-status` span.
    - On `TicketCard` it goes inside the status line. The card's grid has the status on row 2: wrap the status and the time in `<span class="card-meta">` if the grid needs one cell.
    - Styles: `.card-time` uses `var(--font-size-small)`, `var(--color-text-muted)` and `font-variant-numeric: tabular-nums`. Inside `.backlog` it never renders, because backlog tickets have no time. Add `.card-meta` (inline-flex with `gap: var(--space-2)`) if it's used.

- [ ] **Step 3: Docs** as listed.

- [ ] **Step 4: Verify.** Run `npm test && npm run build`. Expected: PASS. Then run the app against a scratch data dir seeded with `tasks.v2.json`, and check by hand (keyboard input via CDP key events):
    1. `tasks.v2.backup.json` equals the fixture, and `tasks.json` is version 3.
    2. Type `0930` (plus AM/PM if the locale needs it) into the time input, then Save. The card and the Day row show `09:30`. A reopened modal shows the time.
    3. Edit an existing time digit by digit. The draft isn't cleared mid-typing (the field doesn't reset).
    4. Clear the time, then Save. No time is shown.
    5. Tick backlog, then Save. The time is gone from the file. Drag a timed ticket into the backlog: its time is gone.
    6. Today's Now ticket with a time shows it. Screenshot a week card with a long title plus a time at 900px width.

- [ ] **Step 5: Commit**: `git commit -m "feat: set a due time in the focus view and show it on tickets"`
